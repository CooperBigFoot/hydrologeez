# Local hybrid HBV checks

2026-11-10, Apple M4 Max (16 cores, 64 GB), macOS 15.7.3 arm64, Python 3.13, PyTorch 2.15.0. CPU and MPS float32 examples; physical parity and finite-difference checks use CPU float64. No NVIDIA execution or external infrastructure.

## KDA provenance

Adapted FLA commit [`b8da4873fa0834849b64938af9f89bc35a347d90`](https://github.com/fla-org/flash-linear-attention/tree/b8da4873fa0834849b64938af9f89bc35a347d90), specifically `fla/layers/kda.py`, `fla/ops/kda/naive.py`, and gate/normalization equations. Full MIT attribution is retained in `src/hydrologeez/hybrid/fla-LICENSE.txt`. Configuration: one head, equal key/value width, supported `use_short_conv=False` path, SiLU projections, additive-epsilon L2 normalization, vector key-coordinate decay, beta delta update, headwise gated RMS normalization and output projection. Decay is applied before residual prediction. This is KDA, not another FLA architecture.

FLA's pinned installation guide lists no MPS backend; its CPU extra still requires import-only Triton plus Transformers. We therefore use one plain-PyTorch implementation, not optimized FLA kernels or multiple execution backends. Upstream initialization constants are retained: exp(A_log) uniform [1,16], dt log-uniform [0.001,0.1], L2 epsilon 1e-6, RMS epsilon 1e-5. These are reference defaults, not hydrological findings.

`tests/data/kda_fla.json` was generated by executing the **unchanged extracted** pinned `naive_recurrent_kda` function (no FLA import), seed 41, float32 `[batch=2,time=5,heads=1,key=value=3]`. It contains all five prepared input tensors, output, final state, and gradients of `sum(output²)+sum(state²)`. The extraction avoids the unrelated einops import/chunk function. The fixture is independently compared in pytest. A hand-computed nonuniform two-coordinate decay case and CPU float64 gradcheck also pass; prefix tests check both encoders' causality.

[kda-oracle.json](kda-oracle.json): maximum CPU output error 8.94e-8, state error zero, all-input gradient error at most 2.38e-7. MPS output error 8.94e-8, state error 5.96e-8, gradient error at most 3.58e-7. Full optimized FLA-layer parity is not established on this Mac.

## Synthetic strategies

Reproduce using `uv run --locked --extra hybrid python -m scripts.hybrid_synthetic` (add `--device mps` for MPS). [cpu.json](cpu.json) and [mps.json](mps.json) retain full results. Each uses two basins, 24 days, three meteorological features, one attribute, hidden width 8, one zone, eight Adam steps per stage at lr 0.01, and 25% independent reconstruction masking. The target is known HBV discharge, not observed hydrological data. Alpha and delta have independent weights.

| Device | Encoder | Direct MSE before → after | Frozen representation / checkpoint / restart max difference |
|---|---|---|---|
| CPU | LSTM | 15.56 → 8.54 | 0 / 0 / 0 |
| CPU | KDA | 9.98 → 0.67 | 0 / 0 / 0 |
| MPS | LSTM | 10.44 → 1.44 | 0 / 0 / 0 |
| MPS | KDA | 12.23 → 3.21 | 0 / 0 / 0 |

All reconstruction and frozen-head steps have finite loss and gradients; their losses decrease in these small checks. CPU and MPS random generation differ, so these are **not device-parity or architecture ranking experiments**. Single-run elapsed training/checkpoint/restart time was about 0.16 s per CPU model and 1.1–1.4 s per MPS model, excluding setup. No speedup claim follows.

The plain recurrence keeps `[batch,heads,key,value]` memory, with O(batch*time*heads*key*value) work and unrolled autograd storage. Long sequences and realistic basin batches were not benchmarked. The tiny oracle MPS run reported 3072 current allocated bytes, **not peak training memory**; no large-scale memory capacity is established. Fine-grained GPU dispatch is costly for these small sequential operations.

## Physical and runtime evidence

Tests compare a worked daily solution and a 24-day snow/rain two-zone sequence to the established NumPy/Numba simulator, including final stores, fractional routing, mass balance and split-run restart. Float64 forward parity tolerance is 1e-12. Parameter and fractional-MAXBAS finite-difference checks pass away from thresholds; empty-store backward remains finite. Other tests prove masked-only target scoring, no hidden-input leakage, intended component updates, encoder freeze under parent train mode, and checkpoint inference equality for both encoders.

Initial dependency setup hit an unrelated stale shared cache lock, then a tslearn isolated metadata-build hang. No unrelated process or cache was removed. `uv lock --no-build-isolation-package tslearn` resolved the existing pinned source using installed setuptools; `uv sync --locked --all-groups --all-extras` then succeeded. Standard locked installation needs no workaround. Linux CUDA packages appear only as platform-specific lock metadata from PyTorch; none were run on this Mac.

See [usage and limitations](../../docs/hybrid-hbv.md). Related: [discussion #174](https://github.com/CooperBigFoot/hydrologeez/issues/174), [Program #170](https://github.com/CooperBigFoot/hydrologeez/issues/170). No regional improvement is established.

Validation: `uv run --locked --all-groups --all-extras pytest -q` → **325 passed**, one existing optional-h5py warning (18.98 s). `uv run --no-sync ruff check .`, `uv run --no-sync ruff format --check src tests scripts`, and `uv run --no-sync ty check` pass. `uv build` succeeds and the wheel contains the FLA notice. Whole-repository markdown formatting also reports pre-existing differences in `docs/cluster.md` and the cluster-count vision, left untouched.
